# Handoff: TeX64 — AI LaTeX執筆アプリ ビルダー画面

## Overview

TeX64は「LaTeXを書けない人でも、AIとの対話だけで学術レベルのLaTeX文書が完成する」アプリ。Base44(ノーコードアプリビルダー)のLaTeX版。

ユーザーはチャットで執筆を依頼し、右側のプレビューに常に**組版済みの紙面**が表示される。ユーザーは紙面そのものをクリックして文章・数式・画像を直接編集する(WYSIWYG)。LaTeXソースは裏側でAIが所有・同期し、前面には出さない。

### 絶対的な設計前提
1. **TeXコードは前面に出さない。** 書ける人向けの補助として「ソースを表示」の小さな導線があるだけ。サイドバーもファイル名ではなく「アウトライン(章立て)」で見せる。
2. **コンパイルは常にAIが完了させる。** ユーザーがコンパイルエラーや警告に対処する局面は存在しない。**エラー表示UI・警告バッジ・ログビューアは作らない。**
3. 装飾は最小限。絵文字・カラフルなチップは使わない。テキストと最小限のアイコンで構成する。

## About the Design Files

このバンドル内のファイルは**HTMLで作られたデザインリファレンス**であり、そのまま出荷するプロダクションコードではない。タスクは、これらのデザインをターゲットコードベースの環境(React/Vue/Svelte等、既存の規約とライブラリ)で**再現実装**すること。環境がまだ存在しない場合は、このプロジェクトに最適なフレームワークを選定して実装する(推奨: React + TypeScript + Vite。数式レンダリングにKaTeX)。

`TeX64 Builder.dc.html` は探索過程を含むデザインカンバス。**実装対象は「7a」(統合版メイン画面)**。他のオプション(1a〜6b)は状態・サブ画面のリファレンスとして参照する。

## Fidelity

**High-fidelity (hifi)。** 色・タイポグラフィ・余白・コピーは最終決定値。ピクセル単位で再現すること。カンバス上のデザインは1600×900の固定アートボードだが、実装はフルードレイアウト(チャット380px固定+右側可変)にする。

## Interactions & Behavior

- **チャット→文書生成**: 送信するとAIが構成プランをチャットに返し、続けて文書を生成。プレビューはビルド中状態→完成した紙面に切り替わる
- **編集/ディスカス切替**: 「編集」= 文書を変更する指示。「ディスカス」= 変更せず相談だけ
- **すべての編集は紙面上で直接**: クリック→インライン編集。ツールバーはコンテキストで出現し、対象の直上/直下に配置
- **Undo/Redo**: ツールバー左上。すべての直接編集・AI編集が履歴に積まれる
- **アウトラインクリック**: 紙面の該当セクションへスムーズスクロール
- **トランジション**: モーダル/ツールバーは150-200ms ease-out(fade+4pxスライド)。派手なアニメーションは使わない
- **ホバー**: リスト項目・ボタンは `background:rgba(255,255,255,.05)` 程度の控えめな変化
- **エラー状態: 存在しない。** AIがコンパイルを常に完了させる前提のため、エラーUI・警告UI・リトライUIは実装しない

## State Management

- `project`: { title, workspace, sections[] (アウトライン), documentModel }
- `documentModel`: 紙面のブロック構造(heading / paragraph / equation / figure / abstract / references)。各ブロックが裏のTeXソース断片とマッピングされる(SyncTeX相当の対応表)
- `chat`: メッセージ配列(user / assistant / status)。statusは「書き込み中 main.tex」等の進捗行
- `buildState`: idle | building(progress) | ready — エラー状態は定義しない
- `selection`: 現在選択中のブロック/テキスト範囲(ツールバー表示位置の決定に使用)
- `mode`: edit | discuss
- 永続化: プロジェクト・チャット履歴・Undoスタックはサーバー保存(プロトタイプ段階ではlocalStorage可)

## Backend Architecture (実装ガイド)

デザイン前提を成立させるための推奨構成:

1. **見た目とコンパイルの分離**: 画面上の即時プレビューはKaTeX等でクライアント描画(体感ゼロ遅延)。本物のLaTeXコンパイルは編集の合間・エクスポート時にバックグラウンド実行
2. **プリアンブル固定+プリコンパイル**: テンプレート/パッケージ構成は製品側で管理しユーザーには触らせない。プリアンブルをフォーマットダンプとして事前コンパイルし全編集で使い回す→毎回のコンパイルは実質本文のみ
3. **エンジン**: サーバー側なら Tectonic(自己完結・再現性の高いビルド)。ブラウザ完結なら SwiftLaTeX系WASMエンジン
4. **AIによるエラー自己修復**: コンパイル失敗はAIがログを読んで自動修正しリトライする内部ループで吸収。**ユーザーには決して露出しない**
5. **ソース↔紙面マッピング**: SyncTeX相当の対応表を維持し、紙面クリック→該当ソース箇所の特定に使う
