# Agents API 開発接続

Code内AxiomとデスクトップAIモードの共通run-loopからAgents APIを使う。
通常起動・配布版の既定経路は従来のTeX64プロキシ。開発用キーを配布版へ組み込まない。

```sh
npm run dev:agents
```

この起動でrenderer、AI画面用のローカルNext.jsサーバー、Electronを起動する。
既存のAIサーバーが応答する場合は再利用する。`TEX64_AI_WEB_URL`でローカルの別ポートを指定できる。
キーはElectronサービスが `TEX64_AGENTS_API_KEY` またはGit対象外の
`services/tex64-ai/.env.local` の `OPENAI_API_KEY` から読み込む。起動スクリプトが
ビルド・watch・AIサーバーへキーを注入することはない。

## モデルと画面

- 画面で選択した `Axiom1.0` / `Axiom1.0-pro` をそれぞれLuna / Terraへ対応させる。
  既定値と上書き用変数名は本番側 `../tex64.com/src/platform/ai-models.js` に合わせる。
  `TEX64_LLM_AXIOM_100_UPSTREAM` / `TEX64_LLM_AXIOM_100_PRO_UPSTREAM` を利用できる。
  本番環境の実値を開発版が自動取得するわけではない。
- 全モデルを一律に上書きする `TEX64_AGENTS_MODEL` は使わない。残っていれば起動時ではなく
  AI接続時に明示エラーにする。reasoning / verbosityも一律lowに落とさず、上流の既定値を使う。
- 開発用キーではTeX64契約の認証・利用枠を使わない。両画面へ開発経路の識別子を渡し、
  標準・Proを選択できるようにする。契約プラン・ログイン・残量を偽装しない。
- ユーザーの依頼からの提案、Ask / Planの権限制限を保持する。文書を開くだけでは推論しない。Codeの会話タイトルは
  `set_chat_title` を本文の処理内で実行し、別のタイトル生成リクエストを買わない。
- 既存の `codex` バックエンドを開発環境変数で横取りしない。

## セッションと復旧

- `environment: none` と `tex64_` 接頭辞の独自function toolsで接続する。
  ファイル操作・組版・undoは既存Electronツールが実行する。
- 同じワークスペース・会話・モデル・指示・ツール構成ではセッションを再利用する。
  新しい発言で過去の全文を再送せず、クラウド側のツール履歴も維持する。
- APIのセッション更新はmetadataのみ。モデル・指示・ツール構成が変わる場合は、ローカル履歴を添えて
  新セッションへ移る。古いセッションのID・利用量は記録に残す。
- ローカル会話保存先と並ぶ `*-managed` ディレクトリへ、セッションID、作成リクエスト識別子、
  実行前後のツール状態・結果、利用量の確定状況を権限600で原子的に保存する。
  UI履歴の件数制限で未処理の停止情報を削除しない。プロセス間ロックで同じ会話の競合を防ぐ。
- ストリーム切断時は再購読してセッション状態を取得する。完了済みなら保存itemsから応答を回収する。
  有料の入力POSTは自動で再送しない。記録済みツールは結果を再利用し、実行途中で失われた操作は二重実行しない。
- Stopは通信の中断とサーバーへのcancelを直ちに開始する。終了待ちに収まらなくても
  `cancel_pending` を保存し、次の起動と次の依頼前に停止を確認する。
  プロセスの強制終了から次の起動までの即時停止を保証するサーバー側期限は、このAPIには指定していない。
- ID受信前の切断は、保存した固有metadataから自分の作成要求を検索する。
  見つからない曖昧な作成を勝手に再送しない。明確な4xx拒否は未作成として扱う。
- 会話削除時は現行・過去セッションを削除する。失敗は記録し、次の起動で再処理する。

## 利用量

通常の文書処理と同じ40区切り・30万トークンの処理枠を使う。試験都合の6区切り・180秒制限は廃止。
`TEX64_AGENTS_DEADLINE_MS` は検証で明示指定する場合だけ有効で、共通の停止処理に連動する。

APIのusageはbest-effortで、未確定のままの場合がある。未確定をゼロとして記録せず、
ローカルには `unknown` と次の処理の見積もりを保存する。受信値も最終請求ではなく暫定値として扱う。
見積もりは実際に渡す圧縮前のメッセージに合わせる。

公開APIには、このセッションの厳密な課金額・内部推論回数・出力トークン数を制限する作成項目がない。
ローカルの枠は厳密な請求上限ではない。TeX64の本番課金との統合・残量表示はこの開発経路には含まれない。
本番切替には別リポジトリ側での利用者別認証・セッション所有権・課金の設計と実装が必要。

## 共通実行ループの変更（2026-09-18）

通常接続とAgents API接続の両方で、提案選択時の一律の編集禁止を除いた。`update_task`、`read_conversation`、`inspect_pdf`を共通ツールとして提供する。AIモードの追加テキストは実行中の区切りで受け取り、次の編集前に反映する。提案不足だけを理由に追加推論しない。文書を開くだけの自動推論は行わない。

モデルの選択と接続先は変更していない。配布版は引き続きプラットフォームのChat Completionsプロキシを使い、Agents APIの直接接続は開発専用。現行プロキシのGPT-5.6ツール互換処理は`reasoning_effort: none`を必要とするため、推論設定の変更は含めない。

後続の提案・実行改修では、実Electronから同じモデルへ10回の実推論を行った。通常の質問からAI自身の具体的な提案が生まれ、クリック後に編集・実組版・PDF観察まで進んだ。検証用の上限で最終返答を止めたため、その後の結果復元は保存済みの実行記録で確認した。これはAgents APIの検証の再実行ではなく、通常ループの新しい動作の確認。状態別の結果と未確認項目は [提案と実行の確認](../output/agentic-20260918/proactive-verification.md) を参照する。
