## 発見した問題と修正状況

1. 元の本文へ完全に戻すと「変更行なし」と「解析失敗」を区別できず、局所更新の継続情報を失った。engine `829706d`で厳密な元の組版との一致を判定し、元の行を通常の証明経路で再描画する修正を実施。904の実機C02/C04で確認した。
2. 自動保存が編集送信より先に完了すると、アプリが子ファイルの新しいoverlayではなく古いoverlayの削除を送る経路がある。旧serverはこの形を局所差分解析前に拒否する。engine `c17fcb2`で、単一の保存済み子ファイル変更を旧入力・実ファイル・保存時刻・差分・適用後入力の一致で厳密に確認する経路を追加した。純粋な再現試験と静的確認は成功。C05の受信body/readPathは当時採取していないため、C05の直接原因と断定しない。同じ操作での修正後実機確認が必要。
3. 初回Build215.309秒のうち約100.6秒は、先に始まった316ページのライブ用openが完了するまでの待機だった。サンプル起動は約1.735秒で別。残り約114.7秒が通常latexmkと成果処理。前者はLuaTeXの途中状態や組版情報を作り、後者は完成PDFを作るため、成果の一部だけ再利用できる。単に前者をBuild後へ移す変更は採用しない。
4. 通常Build中にも背景のiso/renderが動く箇所が残っている。不要な背景処理の競合を減らし、準備済みの局所編集は保持する方針で調査中。
