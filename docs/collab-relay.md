# 共同編集：インターネット越しの中継

LAN / VPN の外にいる共著者とも共同編集できるようにする。今の作り（ホストの Mac が原本を持ち、Yjs の更新を
ゲストと交換する）はそのままにして、ホストとゲストをつなぐ経路だけを足す。

## 方針

- ホストもゲストも、Fermion が置く中継サーバー（Cloudflare Workers + Durable Objects）に外向きにつなぐ。
  中継は部屋（セッション）ごとに 1 つの Durable Object で、ホストとゲストの間でバイト列を流すだけ。
  保存領域は使わない。
- 中身は端末間で暗号化する（AES-256-GCM）。鍵は招待リンクにだけ入り、中継には渡らない。中継が見るのは
  部屋の ID、接続の出入り、暗号文の長さだけ。
- 認証は LAN と同じ。ゲストが最初に送る hello（暗号化済み）の中の編集用 / 閲覧用トークンをホストが確かめ、
  閲覧のみの制限もホストが掛ける。中継は誰が編集できるかを知らない。
- ホストの座は「ホストの秘密」（招待リンクには入れない）で守る。部屋の ID は秘密の SHA-256 の先頭 128 bit
  で、中継はホストがつないだときに秘密からその ID を計算し直して確かめる。秘密を知らなければ部屋の
  ホストにはなれない。
- 中継を使うのは、ホストの TeX64 に中継の URL が設定されているとき（`TEX64_COLLAB_RELAY_URL`）。
  未設定なら今までどおり LAN の経路を使う。ゲストは招待リンクの形で経路を選ぶので、設定は要らない。

## 招待リンク

```
tex64://collab/join?s=<中継の URL>&r=<部屋 ID>&k=<部屋の鍵>&t=<トークン>&n=<名前>
```

`s` は `wss://relay.example` のような ws(s) の起点（パスなし）。`r` は 128 bit、`k` は 256 bit
（どちらも base64url）。編集用と閲覧用のリンクは `t` だけが違う。LAN のリンク（`h` / `p`）はそのまま使える。
中継につなぐ URL は `<s>/rooms/<r>?role=host&secret=…`（ホスト）または `?role=guest`（ゲスト）。

## 中継とのやり取り

ホスト ↔ 中継：1 バイトの種類 + 接続 ID（u16 長 + UTF-8）+ 中身。

| 種類 | 向き | 意味 |
| --- | --- | --- |
| `0x01` SEND | ホスト → 中継 | その接続のゲストへ送る |
| `0x03` CLOSE_PEER | ホスト → 中継 | その接続を閉じる（中身は u16 の閉じる理由コード） |
| `0x11` PEER_OPEN | 中継 → ホスト | ゲストがつないだ（ホストが来たときは待っていたゲスト全員分） |
| `0x12` PEER_DATA | 中継 → ホスト | ゲストからの中身 |
| `0x13` PEER_CLOSE | 中継 → ホスト | ゲストが切れた |

ゲスト ↔ 中継：ゲストが送るものは暗号化済みの塊そのまま。中継からゲストへは 1 バイトの種類 + 中身。

| 種類 | 意味 |
| --- | --- |
| `0x21` HOST_DATA | ホストからの中身 |
| `0x22` HOST_OPEN | ホストが部屋にいる（ゲストは hello を送る） |
| `0x23` HOST_GONE | ホストが部屋を離れた |

ホストがいない間、中継はゲストの接続を保持し、ゲストからの中身は捨てる。ホストがつなぎ直すと、中継は
待っているゲスト全員について PEER_OPEN と HOST_OPEN を送り、ゲストは hello を送り直す。ホストは
welcome を返し、ゲストは今の再接続と同じく状態ベクトルから同期し直す。

閉じる理由コードは LAN と同じ。4004（リンク違い。鍵が違って hello が開けないときも）と 4005（満員）と
1000（ホストがセッションを終えた）はゲストが諦める。それ以外は間隔を空けてつなぎ直す。

## 暗号化と分割

- 1 メッセージ = 12 バイトの nonce + AES-256-GCM の暗号文 + 16 バイトのタグ。追加認証データは向きごとに
  `tex64-collab-relay-v1 host>guest` と `tex64-collab-relay-v1 guest>host`。中継がホストの送ったものを
  ホストへ折り返しても開けない。
- WebSocket の 1 メッセージは Durable Objects の上限（1 MiB）より小さくするため、暗号化した塊を 512 KiB
  ごとに分割する。分割の見出しは「メッセージ番号 u32・何番目 u16・全部で何個 u16」。図版（最大 50 MB）も
  同じ経路で送れる。

## 中継の制限

- 1 部屋のゲストは 10 人まで（LAN と同じ）。中継を通る 1 メッセージは 1 MiB まで。
- Hibernation は使わない（つないでいる間だけ Durable Object が動く）。費用は 1 部屋 1 時間あたり 1 円未満の見込み。

## ファイル

- `services/collab-relay/room.mjs`：部屋の処理。Worker と手元の中継で共有する。
- `services/collab-relay/worker.mjs` と `wrangler.toml`：Cloudflare に置く Worker と Durable Object。
- `services/collab-relay/local-server.cjs`：手元の中継（`node services/collab-relay/local-server.cjs 8787`）。
  テストと、デプロイ前に中継の経路を試すのに使う。
- `electron/services/collab/relay-transport.cjs`：TeX64 側の経路（`RelayHostTransport` /
  `RelayGuestTransport`）。`HostTransport` / `GuestTransport` と同じ口なので、ハブは経路を区別しない。
- `tests/collab-relay.test.cjs`：手元の中継で 2 つのハブをつなぎ、同期・閲覧のみ・中継が平文を見ないこと・
  3 MiB の図版・ホストの再接続・鍵違いのリンク・中継に届かないときを確かめる。

## 残り

本番の中継をデプロイし（Fermion の Cloudflare アカウント）、製品版の既定の経路を中継に切り替える
（LAN は設定で残す）。
