# TeX64 デスクトップのモード

デスクトップ版は **Code と AI** の2面を持ち、トップバーで切り替える。
`tex64.appMode.v1` に最後の選択を保存し、廃止した `pro` 値だけを Code へ移行する。

**一般配布では AI モードを止めている。** パッケージ版はモード切替を隠し、常に Code で起動する
（`electron/main.cjs` の `isAiModeEnabled`: `TEX64_AI_MODE_ENABLED=1` で表示、`0` で開発版でも隠す。
preload が `tex64Bridge.aiModeEnabled` として渡し、renderer は `#mode-switcher` の `hidden` と
初期モードで従う）。コードと markup は残し、削除しない。

- **Code** — LaTeXソース、通常PDF / Liveプレビュー、TikZ、Axiomチャットを扱う。
- **AI** — 同じワークスペースを紙面中心で扱い、会話から執筆・編集・組版する。

Code内のAxiomチャットと課金導線も引き続き提供する。

## AIモード実装の境界

- CodeからAIへ移る前に、開いている未保存バッファをすべて保存する。
- モード切替では実行中の作業を止めない。エージェントのターンも組版もホスト側でそのまま続き、
  戻ったときにAIモードは進行中のターンへ再接続し、Codeは外部変更として結果を取り込む。
  停止境界はプロジェクト切替とウィンドウを閉じるときだけに使う。
- プロジェクト切替では実行中のAxiomと組版を中断し、終了を確認してから切り替える。古い世代の
  組版、ファイル応答、SyncTeX応答は新しいワークスペースへ適用しない。
- AIの会話・紙面・undoは `workspaceId + CodeのrootFile` 単位。AIが書いた内容はCode側の開いている
  Monaco modelにも保存済み内容として反映し、後の保存で古い内容へ戻さない。
- AI専用の文書一覧や作成経路は持たず、Codeの `rootFile` を使う。未設定ならCodeでの設定を求め、別の `main.tex` を推測しない。

## 添付ファイル（画像・PDF・Excel/CSV・テキスト）

- 会話欄の入力欄にクリップのボタンがあり、ドラッグ＆ドロップと貼り付けでも付けられる（最大6件、
  1件 20 MB）。付けたファイルは入力欄の中にチップとして並び、×で外す。
- 送るとき、ファイルはまずワークスペースの `assets/` に保存する（`file:importAttachment`。名前は
  basename に清書し、同名で内容が違えば `-2` を付け、同一内容なら再利用する）。エージェントには
  `[添付ファイル]` ブロックで保存先と要約を渡し、`\includegraphics{assets/…}` で置けるようにする。
- 内容の渡し方はファイル種別で決まる（`services/tex64-ai/src/lib/client/attachments.ts`）。
  画像は長辺 1600px までに縮めて画像として渡す。PDF は先頭3ページを画像に、8ページまでの本文を
  テキストにして渡す。Excel/CSV はシートごとに CSV（200行・全体 12,000 字まで）にして渡す。
  テキスト系はそのまま（12,000 字まで）。画像は合計 8 MB を超える分を省く。
- 添付付きの送信は待機中の吹き出しとして即時に出し、保存と読み取りが済んだ時点でターンが始まる。
  文章が空のときは「添付ファイルを確認してください。」として送る。
- 会話履歴には添付の要約テキストも残る（エージェントの記憶）。表示では `[添付ファイル]` ブロックを
  畳んでファイル名だけを吹き出しの下に出す。
- 会話規則に添付の扱いを足してある: 図は `graphicx` で配置、表の数値は表組みや pgfplots に、画像や
  PDF の文章・数式は読み取れる範囲で忠実に写し、書かれていない数値や事実を補わない。

## 紙面の閲覧と直接編集

- 文書を開くだけではAIを呼ばない。PDFの表示・手動編集・保存・組版・Undoは追加のモデル呼出しなしで行う。
- 紙面は通常のテキスト選択・コピーと内部／外部リンクに対応する。検索、前後ページ・ページ番号指定、倍率指定、幅合わせ、PDF保存と印刷をツールバーから行う。
- 「編集」を選んだ状態で本文を選ぶと、SyncTeXから対応する `.tex` の範囲を開く。編集モードでは本文をキーボードでも選べる。
- 文章と文中数式を保持し、表はセルごとに編集する。文中・独立・表セルの数式はCodeと同じMathLive設定・WYSIWYG候補・キー処理を使う。共通処理は `web-src/math/wysiwyg/field-controller.ts`。分数への変換、行列の行・列追加、候補確定をここに集約し、各画面は入力値の保存を受け持つ。
- 編集カードは「閉じる」とEscapeで下書きを破棄して閉じる。別の破棄ボタンは置かない。保存はボタンとCmd/Ctrl+Sで同じ処理を通る。
- `file:replaceLines` は読取時のcontent hashと対象範囲を照合して書き換える。競合時は下書きを保持し、現在の本文を確認してから適用する。保存成功後の再組版はElectron側で実行する。
- PDF保存は元ファイルをそのまま書き出す。印刷はエディタのレイアウトから独立した印刷面へ全ページを描画する。
- PDFの再描画中も前の版を残す。ウィンドウ幅変更による自動倍率変更でも同じ紙面位置を保つ。
- 組版失敗は原因を一か所に示し、前のPDFがあれば維持する。該当ソースへの移動と再ビルドを提供し、TeXログの行折り返しでも原因・行番号を失わない。
- 実装は `services/tex64-ai/src/components/pdf-preview.tsx`、`pdf-text-layer.tsx`、`paragraph-edit-card.tsx`、`src/lib/client/use-paragraph-editor.ts`。共有数式入力の入口は `web-src/math/wysiwyg/native-editor.ts`。

## 会話からの提案

- モデルは読んだ内容から自発的に `propose_next_steps` で改善案を1〜3件記録する。対象（`scope`）・根拠（`reason`）・変更内容（`change`）・完了条件（`verification`）を必須とし、数式は`previewLatex`で実際の式を表示する。
  返答の `proposals` として会話に永続化する。会話欄は返答の下に行として表示し、行を押すと
  提案内容と完了条件を含む`request`を通常の依頼として送る。会話上は選んだ操作名を表示する。確認ボタンやモーダルは挟まない。
- 提案には `asks` を付けられる。主題・読者・目的・結果など、ユーザーにしか分からない情報が要る
  段はモデルが `asks` に質問を入れ、行を押すとその質問が会話欄に出て、答えを送ると依頼と
  一緒に実行される。空の文書では最初の提案が必ず主題と読者を聞く。
- 固定の「続きを書く」「確認する」は表示しない。文書を開くだけでは推論も通読も行わない。文書の内容を知らない状態で問題を捏造しない。
- 提案が欠けた返答にローカルで補えるのは保存済みの残件だけ。エラー時の再開操作には中断した依頼を表示する。提案を出すだけの追加推論は行わない。
- 古い返答の提案は再実行できない。提案クリックで未送信の文章・添付を消さない。
- 提案の選択は同じ文面を手入力した依頼と同じ権限で実行する。文章の依頼でも必要な情報が揃っていれば編集できる。不足する事実だけを質問する。
- `update_task` で目的・制約・残件・確認結果を会話とともに保存する。直近の履歴にない判断は `read_conversation` で取り出す。確認済みの作業は変更がある場合だけ再確認する。
- `inspect_pdf` は実PDFの指定ページを画像としてモデルへ渡す。1回に最大3ページ、50 MBまで。変更後の組版とPDFの観察が揃うまでは作業を完了にできない。描画しただけでは確認済みにせず、画像を渡したモデルの応答後に記録する。未確認のまま終了しようとした場合の補完は1回までとし、残る問題は未完了として伝える。
- AIモードの実行中に追加したテキストは `agent:steer` で進行中の作業に渡す。モデル応答やツール実行の区切りで反映し、未反映の指示がある間は次の編集・組版を止める。終了済みなら次の依頼として待機する。受付IDで重複を防ぎ、受付結果が不明な指示を自動で別ターンに再送しない。添付ファイル付きの追加依頼は準備後の次ターンに回す。
- 質問は構造化する。モデルは `ask_user`（question / fields / options）でユーザーにしか答えられない
  1問を出してターンを終える。返答は `question` 付きの assistant メッセージとして永続化し、会話欄は
  それを入力カード（選択肢・項目ごとの入力・自由記述）として出す。答えは次の user メッセージ。
  提案の `asks` も同じカードで受ける。
- 提案は `line`（主ファイルの行）を持てる。会話欄の提案行と同じものを、SyncTeX 順引きで紙面の
  余白にも置く（`PdfPreview` の `anchors`）。紙面で押しても会話欄の行を押したのと同じ流れになる。
  順引きは `synctex:forwardBatch` の1往復で全行をまとめて解く。ホストは `.synctex.gz` を組版ごとに
  1回だけ読んで行→紙面位置の索引を持ち（`electron/services/synctex/forward-index.cjs`、PDF の
  mtime で更新）、以後の照会はプロセス起動なしのメモリ参照になる。紙面が出るのと同時に錨が出る。
- 会話欄の提案はキーボードでも選べる。入力欄が空のとき、選択済みの候補だけをEnterで実行し、Tab / Shift+Tabで候補を移り、Escで外す。未選択のEnterでは何も実行しない。
  行にポインタを載せると紙面の錨が、錨に載せると行が、同じ一手として光る。
- 質問が要る提案（`asks` 付き）は行末に小さな「?」を持つ。押すと執筆の前に質問カードが出る。
- 作業中の表示はデスクトップ側のツール名を日本語に写す（「文書を読んでいます」「本文を書いています」
  「紙面を組み立てています」「次の一手を考えています」）。
- 編集の安全層に、`\end{document}` の後ろへの本文追加と2つ目の `\begin{document}` /
  `\documentclass` を拒否する検査を足した。どちらも紙面に出ない「書いたつもり」を生むため。
  `read_file` は `startLine` / `endLine` で行番号付きの抜き出しを返せる。
- 1ターンの予算は 30 万トークン換算・最大 40 反復（`run-budget.cjs` の
  `DOCUMENT_TURN_TOKEN_BUDGET` / `DOCUMENT_MAX_AGENT_ITERATIONS`）。AI モードも Code のチャットも
  同じ。プラットフォーム残量はどちらでも上限になる。
- それでも処理上限で止まったときは行き止まりにしない。次の一手として「続きから進める」を
  決定的に添える（元の依頼文に再開の指示を付けた依頼）。
- 一度 PDF ができた文書の組版は、PDF を守るために隣の作業ディレクトリで走る。作業ディレクトリには
  前回の補助ファイル（`.aux` / `.toc` / `.bbl` など）を持ち込み、成功したら PDF と一緒にワークスペースへ
  戻す（`electron/services/build/pdf-output.cjs`）。目次や参照の変更は latexmk の再実行で追いつき、
  変更がない回は1回で済む。ワークスペースの `.toc` / `.log` も常に最新の組版のもの。
- 組版の成否はエージェントと紙面で同じ基準にする。文字が出ない（missing-glyph）など
  error 級の issue があれば `compile_document` は失敗として返す。最終組版が失敗したターンは、
  エラーを出す前に run-loop が修復を試みる。日本語文書が Latin 系クラスなら
  `ltjsarticle` 系へ決定的に置き換えて組み直し、それ以外はコンパイラの報告を渡して最大2回
  モデルに直させる。

## Code の Axiom サイドバー

- 空のチャットは黙らない。「Axiom」と一行の説明の下に、開いている文書への始め方を4行
  （通読して改善点、組版して修正、数式の記法、参考文献）で並べる。行は依頼文そのもので、押すと
  そのまま送る。入力欄が空のとき Tab で行を選び Enter で送れるが、操作の説明文や kbd は画面に
  書かない（UI は説明ではなく形で分からせる）。文字を打ち始めると選択は消える。
  - ワークスペースが git で、未コミットの変更があるときだけ5行目「変更をレビュー」（変更 n ファイル）
    が出る。押すと Ask として走り、`git_diff` で差分を通読して `file:line` 付きで指摘だけする。
  - 行の下に「この文書の書き方の規則」の一行。押すと `.tex64/rules.md` を（無ければ雛形から作って）
    エディタで開く。無いときは「まだありません」を添える。存在と git の変更数は
    `agent:documentMap:get` の応答（`git` / `rules`）で知り、空の状態を描くたびに求める。
- 入力欄は2段の板。上が文章（最小2行、自動で伸びる）、下が操作列。左にクリップ・マイク・文脈チップ
  （ファイル名・カーソル位置または選択範囲・PDF の場所）、右にモードのピル（Agent / Ask / Plan）、
  モデル名、送信。ピルの語は製品語なので訳さない（`data-no-i18n`）。
  送信ボタンは文字か添付があるときだけ出る。モデルのメニューは入力欄から上へ開く。フォーカスは
  枠の色だけで示し、リングは付けない。プレースホルダと操作の title は markup 側に置き、ロケール
  辞書（`web-src/app/i18n.ts`）で訳す。実行時に差し替える属性は `setLocalizedAttribute` で
  英語の原文を渡す（属性の観察者が原文から訳し直すため）。
- **Agent / Ask / Plan**。Agent は編集して組版する。Ask は読むだけで、書き込みと組版のツールをモデルに
  見せず、呼ばれても拒否する（`context.axiomMode`、`localStorage` の `tex64.axiom.mode` に保存）。
  Ask のプレースホルダは「質問を書く。文書は変更しません」。
  Plan も読むだけで、モデルは `record_plan` で3〜8段の計画（場所・何を書くか・利用者にしか
  答えられない問い）を記録し、返答の下に**計画カード**として出る。各段はチェックで外せ、
  「計画に足すこと・変えること」の一行を添えて「この計画で進める」を押すと、ピルが Agent に
  切り替わり、残した段と補足をひとつの依頼として送る（`plan_run_request`）。Plan では
  `propose_next_steps` を載せない。プレースホルダは「まず計画を立てる。まだ書きません」。
- **@** は文書の中身を指す。節（番号・題・行範囲）、`\label`、ファイル、bib の項目、直近の Issues を
  種類ごとにまとめて出し、選ぶと `@§定式化` / `@fig:sales` / `@knuth84` のような手掛かりを本文に入れ、
  正確な場所（`explicitContextRefs`）を依頼と一緒に送る。索引はピッカーを開いた時にホストへ
  `agent:documentMap:get` で求める（文書マップの節・ラベル・bib キー）。
- **選択して聞く**。エディタで .tex の範囲を選ぶと選択末尾に「Axiom に聞く」の小さなボタンが浮く
  （右クリックメニューと ⌘K も同じ）。押すと Axiom タブが開き、入力欄にフォーカスが移り、
  文脈チップに選択範囲が出る。選択本文は依頼に添える。
- **紙面の場所を指して聞く**。PDF でも同じボタンが出る。通常の PDF ビューアでは文字を選ぶと
  選択末尾に浮き（右クリックメニューにも「Axiom に聞く」）、押すとホストが SyncTeX 逆引き
  （`synctex:reverse`、requestId `ask-axiom:*`）でソース行を引く。リアルタイムプレビュー（TDOM）では
  紙面の文字を選ぶか右クリックすると、エンジンが選択・位置とソース行を親へ渡し
  （`action: 'place'`）、同じボタンが浮く。押すとソース行はそのまま使う（SyncTeX は呼ばない）。
  どちらも文脈チップ「p.N · main.tex:L」（× で外せる）になり、依頼には REFERENCED ITEMS として
  「利用者が紙面で指した場所＝ソースの path:line と、そこにある文」を添える。依頼文の「ここ」はこの
  場所を指す。送ったらチップは消える。
- **マイク**。押すと録音（赤い表示と経過時間）、もう一度押すと止めてホストへ渡し、文字になった
  ものが入力欄のカーソル位置に入る（送信はしない）。ホストは `agent:transcribe` で
  `tex64.com/api/v2/ai/openai/audio/transcriptions`（multipart、認証は chat と同じ）へ送る。
  マイク不許可や失敗は入力欄の上の一行で伝える。
- ユーザーの発言は幅いっぱいの薄い板、返答は本文。返答の下にホバーで「コピー」「やり直す」
  「良い返答」「いまいち」「ここから分岐」と相対時刻が出る。
  - 評価は `agent:feedback` でホストへ渡り、設定のフィードバックと同じ `POST /api/v2/feedback`
    （category `axiom-rating`、diagnostics に依頼文と返答の抜粋・モデル・会話 id）で開発チームに届く。
    「いまいち」は任意の一言を書く小さな箱を開き、送る前に「依頼文と返答が送られる」と明記する。
    評価は会話に永続化し（assistant entry の `rating`）、再起動後も表示に戻る。
  - 分岐は `agent:branch`。その返答までを複製した新しいチャットをホストが作り、開く。履歴では
    「別のチャットから分岐」と出る。
- **作業中に送った依頼は待たせる**。実行中に送ると同じチャットの後ろに「待機中」の板として並び、
  ターンが終わると自動で送る。板の ▶ で今すぐ送り、× で取り消す。新しいチャットは作らない。
- **次の一手**。返答の下に、モデルが `propose_next_steps` で記録した行（番号・題・範囲、質問が要る
  ものは「?」）を見出し無しで幅いっぱいに並べる（文字を途中で切らない）。最新の返答の行だけが
  Tab / Enter に応える（空のチャットの始め方と同じ操作）。質問付きの行は押すと質問カードが開き、
  答えと一緒に依頼を送る。`ask_user` の質問も同じカード。
  - 各行には `kind`（`mechanical` / `writing`）がある。種別で編集ツールを隠さず、通常の依頼と同じ実行ループに渡す。Ask / Planの読み取り専用制限は維持する。
  - Codeでも提案が欠けた場合に補えるのは保存済みの残件だけ。提案だけの追加推論は行わない。
- **履歴の題**はモデルが付ける。最初の返答が出た後に短い非ストリーミング呼び出しで3〜6語の題を
  作り（`electron/services/agent-conversation-title.cjs`）、`agent:title` で届いて上部と履歴に出る。
  セッションに永続化する。届くまでは依頼文の先頭で仮置き。履歴行には相対時刻を添える。
- ツールの活動（読み取り・書き換え・組版）は `🔧` 印のシステム行として会話に残し、表示では
  連続する行を「作業の記録 N」に畳む（`.ai-trace`）。次の一手や質問の記録は作業ではないので載せない。
  作業中は小さなリングと薄い一行。
- 添付は入力欄の中にチップ（サムネイル・名前・サイズ・×）で並ぶ。実行中でも付けられる（待機中の依頼と一緒に送る）。
- 変更は確認なしでそのまま書く。エディタ側に「元に戻す／完了」のバーは出さない（変更行の
  ハイライトだけ残り、次の編集で消える）。変更カードは**その返答の中**に置く（`message.changes`）。
  実行中は末尾の仮カードに集め、返答が確定したら返答へ移す。カードは返答と同じ幅（内容に合わせて
  縮めない。チップやカードの幅を制限しない）。カードには「差分」（閲覧のみ）と、
  最新の返答のカードにだけ「元に戻す」（`agent:undoLastRunApply`）。次の依頼を送ってもカードは
  その返答に残る。戻したらそのカードは消え、「変更を元に戻しました。」の一行が残る。
  - カードの一行に**どこを変えたか**を出す。書き込み時にホストが最初の変更行とその節を
    `proposal.scope` に付け（`electron/services/agent-proposal-scope.cjs`）、組版が成功したら
    SyncTeX 順引き索引でページを引いて `agent:proposalScope` で足す（「§ まとめ · 1ページ」）。
- エラーがある間は Issues タブに赤い点を表示し、解消したら消す。詳細は Issues パネルで確認できる。
- 編集後の報告は変更箇所・組版結果・残った問題を短く伝える。質問への回答には文数制限を設けず、
  必要な LaTeX 例・数式の途中式・対象箇所に即した具体的な説明を返す。
- ターンがエラーで終わったときだけ、その理由をシステム行として一行残す（API のエラーなど）。
  「送れなかった入力を復元しました」は出さない。送った依頼はホストが受け取った時点で下書きでは
  なくなり、途中で止まっても入力欄に戻さない。「続きから進める」ボタン（▶、アクセント色）で再開する。
- 履歴（時計）を開いた状態で「+」を押すと履歴が閉じて新規チャットになる。
- 利用量の円形メーターとログインのオーバーレイは無い。ログインが要るときは入力欄の上に一行と
  「Google でログイン」だけを出し、送信もログインを始める。残量の注意はチャットに出さない
  （利用量は設定 › アカウント › AI チャットだけ。頻繁に見るものではなく、チャットの邪魔になる）。
  利用量はターンの終わりにホストが押し出す（`platform:usage` / `platform:aiAccess`、source "turn"）ので、
  レンダラーはターンごとに `platform:usage:get` を投げない。
- ホストの状態スナップショット（`agent:state`）はワークスペースのルートが変わったときだけ求める
  （ファイルツリーの更新ごとには求めない）。開いているチャットと進行中のターン、待機中の依頼は
  それをまたいで保つ。エディタ文脈は dirty なファイルの本文だけを送り、保存済みはパスだけ。

## エージェントの働き方（Code / AI 共通の run-loop）

開発時のAgents API接続は [agents-api-trial.md](agents-api-trial.md) を参照する。
両UIでモデル選択・ユーザーの依頼からの提案・ツール実行・組版・undoを保持する。
開発接続の会話継続・停止・利用量の扱いは上記資料を参照する。

- **文書マップ**。ターンの最初に主ファイルから `\input` / `\include` を辿って文書全体を決定的に
  走査し（`electron/services/agent-document-map.cjs`）、節と行範囲（id 付き）、float、ラベル、引用、
  bib の項目数と鍵をモデルの入力に添える。モデルは `read_section` か行範囲で目的の場所へ直行する。
  書き込みのたびに再走査し、書き込み系ツールの結果には変更後のファイルの見出しと行範囲
  （`outline`）を付けるので、読み直さなくても行番号が分かる。
- `read_file` の全文読みは1ターンに同じファイル1回まで。2回目は行範囲か節で読むよう促す短い
  応答と見出しだけを返す。同じ読み取り（同じツール・同じ引数）の繰り返しは「前回と同じ」で済ませ、
  編集なしの読み取りが8回続いたら一度だけ編集を促す。
- **返答の種別はモデルが宣言する**。最終返答の先頭に `[edit]`（このターンでファイルを変えた）か
  `[report]` を置かせ、表示前に取り除く（ストリーミング中は先頭の数文字を保留して判定）。
  `[edit]` なのに書き込みツールが一度も成功していない返答だけを差し戻し（最大2回、
  `agent:messageReset` で流れた文を消して作業中の行に戻す）、質問への回答が「〜しました」を
  含んでも巻き込まない。以前の言い回しの正規表現は撤去した。
- **ツールは要る回だけ載せる**。`arxiv_search` / `arxiv_bibtex` は会話に文献・引用・arXiv の
  話題があるとき、`check_environment` は環境やコマンドの話題があるときだけ一覧に入れる
  （`OPTIONAL_TOOL_GROUPS`）。載っていなくても呼ばれれば実行はする。`git_diff`
  （`git status --porcelain` と作業ツリー・index の統合差分、6万字まで）はワークスペースが git の
  ときだけ、`record_plan` は Plan のときだけ載せる。Ask / Plan / 書く一手の最初のターンでは
  書き込み系と `compile_document` を外し、呼ばれても理由付きで拒否する。
- **プロジェクトの書き方の規則**。`<root>/.tex64/rules.md` があれば毎ターン読み、
  PROJECT WRITING RULES として（4000字まで）システムプロンプトに添える。
- `compile_document` はコンパイラのログをそのまま返さず、issue ごとに `path:line` と前後2行の
  ソース抜粋（`>` 付き）を返す。解析できた issue があるときは長いログ末尾を付けない。
- `check_references`（`\label` / `\ref` / `\includegraphics` / ラベルの無い float）と
  `check_bibliography`（`\cite` と bib の突合、未使用・重複・必須フィールド欠落）は決定的に
  `file:line` を返す。
- 同じソースの組版は繰り返さない。文書マップのファイル群の指紋（sha256）を成功した組版ごとに
  記録し、ターン末の自動組版は指紋が変わっていなければ省く。
- 消費済みの古いツール呼び出しの引数は、長い文字列を「N行・M文字・先頭行」に置き換えて再送する
  （`run-budget.cjs` の `compactToolArguments`）。古いツールの**結果**は残す（最終返答は差分や節の
  中身から書かれるため）。6000字を超える結果だけ先頭4000字に切り、「必要なら呼び直す」を添える。
- **アクセス確認はターンに1回**。`checkAiAccess({force:true})` はターンの最初だけ。残量はプロキシの
  応答ヘッダ `X-Tex64-Quota-Remaining-Tokens` / `X-Tex64-Quota-Limit-Tokens` から取り、課金対象の
  トークン（キャッシュ済みプロンプトは半分）をターン末にまとめて `noteAiUsage` で反映し、
  レンダラーへ押し出す。
- **ツール活動は名前だけ送る**。ホストは `{name, detail}` を送り、各 UI（Code は `ai-i18n` の
  `tool_*`、AI モードは `TOOL_ACTIVITY_LABELS`）が自分の言葉に直す。ホストに英語ラベルは持たない。
- **SyncTeX 逆引き**は順引き索引（ページごとの glyph / box 記録）で先に引く
  （`SynctexService.prototype.reverseQuick`、`forward-index.cjs`）。当たらないときだけ外部の
  `synctex edit` に落ちる。
- システムプロンプトは短くした（`agent-prompt-utils.cjs`）。ツール一覧は関数スキーマに任せ、
  「編集の合間に読み直せ」は「変えた範囲だけ」に、「構造の削除は Code で手動」は「白紙化の依頼が
  あれば前文だけ残す」に改めた。節の本体は `\bibliographystyle` / `\bibliography` /
  `\printbibliography` / `\appendix` の手前で終わる（`replace_section` が参考文献の命令を巻き込まない）。
  `append_to_section` は本文の最後の行の後ろに段落をひとつ空けて足す。

## 認証・課金・モデル

編集後の組版結果には、SyncTeXで取得できた変更ページを含める。`inspect_pdf`でそれらの画像をモデルが受け取るまで、作業記録を完了にしない。確認済みの記録は後続のターンでも参照する。最後の返答だけが通信エラーで失われた場合、完了記録から結果を復元し、同じ編集や推論をやり直さない。

入力予算は、既知のモデルではトークナイザーに余裕を加えて見積もる。未知のモデルには従来のバイト数による上限を使い、画像分の予算も残す。利用枠の最終判断はプラットフォーム側で行う。

Code内のAxiomで見せるモデルは `Axiom1.0` とPro限定の `Axiom1.0-pro` の2つ。認証、AI利用可否、
トークン利用量、プラン変更はCodeと同じElectron側の課金実装へ接続する。利用量として表示するのは
トークンだけで、内部コストやドル予算は出さない。

- 利用量は設定 › アカウント › Axiom に置く。プラン名、今月の使用量のバー（使用 / 上限トークン、%）、
  リセット日、「プランを開く」。数値はチャットと同じ `platform:usage` / `platform:aiAccess` から取る
  （`web-src/app/settings-ui/account-usage-ops.ts`）。
- ログイン導線は設定 › アカウントの Google ログインと、チャット入力欄の上の一行の2つだけ。
- ロック中の Pro モデルを押したときのカードは「Pro プランで使えます」と「Pro プランを見る」だけ。
- 設定ファイルの `agent` に残るのは `model` だけ。反復回数・自動適用・自動組版・ファイル上限・
  ブロックする階層・エンドポイントはエージェントの性質としてコードに固定した
  （`agent-policy.cjs` / `agent.cjs`、古い鍵は読み込み時に捨てる）。開発者だけが
  `TEX64_LLM_ENDPOINT` / `TEX64_LLM_API_KEY` / `TEX64_LLM_MODEL` の環境変数で接続先を変えられる
  （プロキシ以外に向けたときは Axiom の別名ではなく `TEX64_LLM_MODEL` の名前で呼ぶ）。

## アプリへの同梱

`services/tex64-ai` のNext.js standalone出力をアプリへ同梱し、ElectronがローカルUIサーバーとして起動する。
外部AI UIへフォールバックせず、ワークスペースのファイル取得はElectronの許可制bridgeだけを通す。

## bridgeの実装上の注意

- `electron/ai-web-preload.cjs` → `web-src/app/ai-mode-ui.ts` → mainの許可制メッセージ経路を使う。状態の取得は `workspace:state:get`。フォルダ選択ダイアログを開く `requestWorkspace` / `openWorkspace` をゲストに許可しない。
- `requestFromHost` は応答のpayloadを返すので、再度アンラップしない。ホストは最後のワークスペース状態を保持し、後から起動したゲストにも渡す。
- PDFはワークスペース識別情報付きの専用bridgeで取得し、別ワークスペース・別文書の遅延応答を捨てる。
- 開発起動・生成物・検証の方針は [../AGENTS.md](../AGENTS.md)。`Resources/web/index.html` と `Resources/web/theme.css` は直接編集する。
