# macOS のファイルアクセス許可

macOS は Desktop、Documents、Downloads、iCloud Drive、外付けボリュームなどを TCC（Transparency, Consent, and Control）で保護しています。TeX64 がそこにあるプロジェクトを開くと、macOS がファイルアクセスの許可を確認します。

TeX64 は、ユーザー操作と無関係に保護フォルダを探索しません。アクセスが必要になった時点でだけ確認し、同じ保護 root に対する同時要求を一つにまとめます。一度許可または拒否した root は、そのアプリセッション中には再確認しないため、許可ポップアップは root ごとに最大一回です。

拒否した後で許可する場合は、TeX64 の案内から「システム設定を開く」を選ぶか、macOS の「システム設定」→「プライバシーとセキュリティ」→「ファイルとフォルダ」で TeX64 のアクセスを有効にしてください。その後 TeX64 を再起動します。

## ローカル開発版の安定署名

ローカル配備を繰り返す開発環境では、最初に一度だけ次を実行できます。

```bash
npm run sign:local-identity
```

このセットアップは `TeX64 Local Signing` という自己署名 ID と専用キーチェーンを作ります。信頼設定の追加時に macOS のログインパスワードを一回求められます。状態だけ確認する場合は `npm run sign:local-identity:status` を使います。

このセットアップをしない場合、ローカル配備は ad-hoc 署名へフォールバックします。ad-hoc 署名の designated requirement はビルド内容の cdhash に依存するため、再ビルドのたびに macOS から別のアプリと見なされ、以前の TCC 許可が引き継がれません。安定した証明書ベースの署名を使うと、再ビルド後も同じ署名主体として扱われます。
