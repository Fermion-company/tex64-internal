# AI モードで実際に論文が書けるか（受け入れ基準）

AI モード（`services/tex64-ai`）の完成度は、**自然言語のチャットと PDF 上のクリックだけで、
投稿できる水準の論文が最後まで書けるか**で判定する。機能の一覧ではなく、実際に 4 本書き切る。

判定の原則:

- ユーザーは **LaTeX を一行も書かない・見ない**。ソースを触らせた時点でその項目は不合格。
- 「できた」は **PDF が出た**ではなく、**人手で直さずに出せる紙面になった**。
- 詰まったら、そこで止めて原因を記録する。回避策で先へ進んだ項目は合格にしない。
- できた項目からチェックを埋める。NG は理由と再現手順を残し、直したら再走する。

## 題材と書き方

### 論文A — 理論・数式主体

**テーマ案**: 拡散モデル（DDPM と DDIM）の統一的整理。実験を持たず、定義・命題・導出だけで構成する。

| | |
|---|---|
| 主眼 | 数式表現が実用に耐えるか。ここが落ちると他は無意味 |
| 使う要素 | `equation`(aligned/script/integral/largeOperator/statisticalOperator/cases)、`theorem`、`proof`、`inlineMath`、`crossRef`(式番号参照) |

**書き方（チャットのみ）**

1. 主題だけ渡す —「拡散モデルの DDPM と DDIM を統一的に整理した論文を書いて」
2. 出た紙面を読んで章単位で詰める —「第3節の逆過程の導出、途中式が飛んでいるので2段階細かく」
3. 構造を要求する —「この命題を定理として立てて、証明を別に分けて」
4. 参照を要求する —「式(4)を本文から参照して」
5. 表記の統一 —「条件付き分布の書き方が節ごとに違う。q(x_t | x_{t-1}) の形に揃えて」

**完成条件**: 8〜12ページ。式番号が本文から参照され、導出に飛躍がなく、記号が全節で一貫している。

### 論文B — サーベイ

**テーマ案**: 日本語 LLM の評価ベンチマークの動向。

| | |
|---|---|
| 主眼 | 出典の扱いが実運用に耐えるか。**この環境の最大の弱点を突く題材** |
| 使う要素 | `citation`、`bibliography`、`citationRef`、`resolve_source`、引用スタイル切替 |

**書き方（URL をユーザーが供給する）**

1. 範囲を渡す —「日本語 LLM の評価ベンチマークのサーベイを書きたい。まず構成案を出して」（＝書かずに答えられるかの確認も兼ねる）
2. 出典を貼る —「この arXiv を読んで、2.1 節に2段落で位置づけて」＋ URL
3. 主張と出典の対応を要求する —「この段落の主張、どの文献が支えているか本文中で示して」
4. 最後に体裁 —「参考文献を IEEE 形式に。本文の引用番号も揃えて」

> **既知の制約**: `search_sources`（文献検索）は AI Gateway 資格情報がある環境専用で、いまのローカル/OpenAI 直結では**使えない**。
> URL・DOI はユーザーが渡すか、モデルが知っているものを `resolve_source` で確認する経路しかない。
> 「文献探しから任せられるか」はこの構成では判定できないので、**別途ゲートウェイ環境で確認する**。

**完成条件**: 引用がすべて実在の取得済み出典に紐づき、本文の引用と参考文献リストが一対一で対応している。

### 論文C — 実験報告

**テーマ案**: TeX64 の数式サジェストの打鍵シミュレーション結果（実データが社内にある。arXiv 85 ファイル・11,386 出現・top-1 97.3% → 99.9%）。

| | |
|---|---|
| 主眼 | 図表とデータの取り回し。手で数値を貼って紙面になるか |
| 使う要素 | `table`、`figure`(chart: line/bar)、`algorithm`、`codeBlock`、`callout`、`appendix` |

**書き方（数値を会話に貼る＋PDF クリック）**

1. 数値を貼る —「この結果を表にして。列は手法／top-1／MRR」
2. 図にする —「改善前後を棒グラフに。縦軸は top-1 率」
3. 手順を書かせる —「評価手順を algorithm として書いて」
4. **PDF 上の表をクリック** して —「この列は要らないので落として」
5. **手動でブロックを直して** 紙面が自動で追随するか確認
6. 版を戻す —「さっきの表の変更を取り消したい」→ 変更履歴から復元

**完成条件**: 図表が本文から参照され、貼った数値が改変されずに出ている。

### 論文D — 投稿規定つき和文短報

**テーマ案**: 学会予稿（2ページ、A4、2段組）。テーマは A か C の要約でよい。

| | |
|---|---|
| 主眼 | 体裁と分量の制御。エージェントが自分で組版結果を見て調整するか |
| 使う要素 | `format_document`(academic / A4 / 2段組)、`compile_document` の `pageCount` 自己確認、`pageBreak` |

**書き方**

1.「A の内容を2ページの予稿にまとめて。A4・2段組」
2. はみ出したら —「2ページちょうどに収めて」（自分で組版して確認・調整するかを見る）
3.「節見出しの体裁を学会向けに」

**完成条件**: 指定ページ数ちょうど、はみ出し・空白ページなし。

## 横断で確認する操作

論文 A〜D を書く過程で、以下がすべて自然に成立していること。

- [ ] チャットだけで最後まで進む（LaTeX を見せられない・書かされない）
- [ ] 質問・相談には**書かずに文章で答える**（勝手に紙面を作らない）
- [ ] PDF の要素をクリック → その要素だけが変わる
- [ ] 手動でブロックを編集 → 紙面が自動で追随する
- [ ] 版の復元 → 紙面がその版に戻る
- [ ] 実行中に停止できる／実行中に次の依頼を送れる
- [ ] 長い執筆でも会話の文脈を失わない（前の決定を聞き直さない）

## いま分かっている上限

論文を書く前から分かっている制約。これに当たったら「アプリの不足」として記録する。

- **画像を貼れない**。`figure` は `flowDiagram` と line/bar チャートのみで、写真・スクリーンショット・外部で作った図は載せられない（`assetId` は既存資産の参照専用）。実験系の論文では致命的になりうる。
- **文献検索が使えない**（この環境）。上記 B を参照。
- **文書クラスは `ltjsarticle` 固定**。IEEEtran や各学会のスタイルファイルは選べない。「投稿できる」の水準はここで頭打ちになる。
- **段組は 1 か 2、用紙は A3/A4/A5/B4/B5/letter**。それ以外の指定はできない。
- 使えるパッケージは amsmath / amssymb / graphicx / booktabs / array / ulem / geometry と、必要時に xurl / tabularx / longtable / amsthm / tikz / pgfplots。
