# AI モードで学部量子力学の教科書が書けるか（受け入れ基準）

AI モード（`services/tex64-ai`）の完成度は、**自然言語のチャットと PDF 上のクリックだけで、
学部レベルの量子力学の教科書を一冊書き上げられるか**で判定する。機能の一覧ではなく、実際に書く。

論文一本と違い、教科書は次を要求する。ここが本当の試験になる。

- **数百ページ規模の一貫性** — 記号、用語、書式が全章で揃っていること
- **章をまたぐ参照** — 「第3章で示したように」「式(4.12)より」が正しく解決すること
- **段階的な構築** — 何十回も継ぎ足す。過去の決定を覚えていること
- **教科書固有の構造** — 目次、章末問題、解答、記号一覧、索引、参考文献

判定の原則:

- ユーザーは **LaTeX を一行も書かない・見ない**。ソースを触らせた時点でその項目は不合格。
- 「できた」は PDF が出たことではなく、**人手で直さずに配れる紙面になった**こと。
- 回避策で先へ進んだ項目は合格にしない。詰まったらそこで止め、原因を記録する。
- できた項目からチェックを埋める。NG は理由と再現手順を残し、直したら再走する。

## 段階と、当たりに行く壁

一冊いきなり作らない。段階ごとに**壊れる場所を特定する**のが目的。

### S1 — 1章だけ（第4章 調和振動子、15〜20ページ）

**狙い**: 数式表現が実用に耐えるか。ここが落ちたら以降は無意味。

**打つ指示**

1.「学部向け量子力学の教科書の第4章として、調和振動子の章を書いて。代数的解法から座標表示、不確定性まで」
2.「\\([a,a^\\dagger]=1\\) からエネルギー固有値を出すところが飛んでいる。数演算子の固有値が非負整数になる理由を段階的に」
3.「基底エネルギーが \\(\\hbar\\omega/2\\) になることを定理として立てて、証明を分けて」
4.「エルミート多項式の漸化式の式を、座標表示の節から参照して」
5.「\\(\\langle x^2\\rangle\\) と \\(\\langle p^2\\rangle\\) の書き方が節ごとに違う。期待値は \\(\\langle\\cdot\\rangle_n\\) に統一して」
6.「章末問題を5問。うち2問は計算問題、3問は導出問題」

**想定する壁**: 数式 AST（`statisticalOperator` / `aligned` / `script`）でのパッチ拒否。実測で1回発生済み。

---

### S2 — 3章まとめて（第3・4・6章）

**狙い**: 章をまたぐ一貫性と、**文書サイズが効き始める点**。

**打つ指示**

1.「第3章として1次元問題（自由粒子・無限井戸・有限井戸・トンネル）を追加して。第4章の記号に合わせて」
2.「第6章として不確定性関係を追加。第4章で出した \\(\\Delta x\\Delta p\\) の結果を一般化する形で」
3.「第6章から第4章の不確定性積の式を参照して」
4.「3章通して \\(\\psi\\) と \\(\\varphi\\) の使い分けが揺れている。束縛状態は \\(\\psi_n\\) に統一して」

**想定する壁**: `read_document` が**文書全体**を返す設計。3章（推定 60 ページ = JSON 20〜35 万字）で毎ターン全文が文脈に載る。**ここで確実に詰まる**。
→ 当たったら**章・節単位の部分読み**を実装する（優先度最高の改修）。

---

### S3 — 章末問題と解答（付録 B）

**狙い**: 相互参照の量が一気に増える。教科書固有の構造。

**打つ指示**

1.「各章の章末問題の解答を付録Bにまとめて。問題番号と対応づけて」
2.「付録Bの解答から、本文の該当する式を参照して」
3.「第4章の問題3、解答が本文の導出と重複している。本文を参照する形に短くして」

**想定する壁**: `crossRef` の対象は section / equation / theorem / figure / table のみ。**問題番号への参照は表現できない**可能性が高い。

---

### S4 — 全15章

**狙い**: 規模そのもの。

**想定する壁**（実測に基づく見積り）

| 上限 | 値 | 教科書換算 | 判定 |
|---|---|---|---|
| 文書 JSON | **2 MiB** | 数式中心で **約 360 ページ**、散文中心で約 820 ページ（実測 578 chars/ノード） | 15章なら**ぎりぎり収まる** |
| 版数 | **500 版/文書** | 1パッチ＝1版。15章＋推敲で**確実に超える** | **要改修** |
| コンパイル | **45 秒**（ローカル） | 300 ページ＋tikz/pgfplots で超える見込み | 要計測 |
| PDF | 32 MiB | 問題なし | OK |

---

### S5 — 目次・索引・記号一覧

**狙い**: 教科書として配れる形になるか。

**想定する壁**: レンダラは `\tableofcontents` を出さない。索引（`makeindex`）の仕組みも無い。
→ **目次・索引は現状では作れない**。ノード型かレンダラの追加が要る。

## 横断で確認する操作

- [ ] チャットだけで最後まで進む（LaTeX を見せられない・書かされない）
- [ ] 質問・相談には**書かずに文章で答える**（勝手に紙面を作らない）
- [ ] PDF の要素をクリック → その要素だけが変わる
- [ ] 手動でブロックを編集 → 紙面が自動で追随する
- [ ] 版の復元 → 紙面がその版に戻る
- [ ] 実行中に停止できる／実行中に次の依頼を送れる
- [ ] **何十ターン後も前の決定を覚えている**（記号の取り決め、章構成）

## いま分かっている上限（実測値つき）

書き始める前から分かっている制約。当たったら「アプリの不足」として記録し、直す。

**規模**

- 文書 JSON **2 MiB**（`MAX_DOCUMENT_SERIALIZED_BYTES`）。実測 578 chars/ノードから、数式中心で **約 360 ページ**が上限。
- **500 版/文書**（`MAX_REVISIONS_PER_DOCUMENT`）。1 パッチ＝1 版なので、教科書規模では**足りない**。
- ローカル組版 **45 秒**（`COMPILE_TIMEOUT_MS`）。

**構造**

- **`read_document` が文書全体を返す**。章単位の部分読みが無い。S2 で最初に当たる壁。
- 文書クラスは **`ltjsarticle` 固定**で、`\chapter` が無い。章立ては `section` の入れ子で代用し、**式番号は通し番号のみ**（式(4.12) のような章別番号にならない）。
- **目次・索引を出す仕組みが無い**。
- `documentType` に「教科書」に相当する値が無い（article / proposal / report / paper / letter / notes）。

**表現**

- **画像を貼れない**。`figure` は `flowDiagram` と line/bar チャートのみ。ポテンシャル図・軌道の可視化は自前で描けない。
- **文献検索が使えない**（`search_sources` は AI Gateway 資格情報がある環境専用）。参考文献は URL・DOI をこちらが渡す。
- 段組は 1 か 2、用紙は A3/A4/A5/B4/B5/letter。
- 使えるパッケージは amsmath / amssymb / graphicx / booktabs / array / ulem / geometry と、必要時に xurl / tabularx / longtable / amsthm / tikz / pgfplots。
