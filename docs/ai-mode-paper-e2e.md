# AI モードで実際に論文が書けるか（受け入れ基準）

AI モード（`services/tex64-ai`）の完成度は、**自然言語のチャットと PDF 上のクリックだけで、
投稿できる水準の論文が最後まで書けるか**で判定する。機能の一覧ではなく、実際に 4 本書き切る。

判定の原則:

- ユーザーは **LaTeX を一行も書かない・見ない**。ソースを触らせた時点でその項目は不合格。
- 「できた」は **PDF が出た**ではなく、**人手で直さずに出せる紙面になった**。
- 詰まったら、そこで止めて原因を記録する。回避策で先へ進んだ項目は合格にしない。
- できた項目からチェックを埋める。NG は理由と再現手順を残し、直したら再走する。

## 題材と書き方

題材は**学部レベルの量子力学**で揃える。4 本とも、その分野の学生が実際に書く形の文書にする。

### 論文A — 理論・数式主体

**テーマ**: 1次元調和振動子 — 生成消滅演算子による代数的解法と不確定性関係

| | |
|---|---|
| 主眼 | 数式表現が実用に耐えるか。ここが落ちると他は無意味 |
| 使う要素 | `equation`(aligned 導出 / `script` で \(a^\dagger\), \(x_n\) / `integral` 規格化 / `largeOperator` 級数 / `statisticalOperator` 期待値・分散 / `cases`)、`theorem`、`proof`、`inlineMath`、`crossRef`(式番号参照) |
| なぜこれか | 交換関係 → 数演算子 → 固有値 → 座標表示 → 不確定性、と**導出が一本道で段階が明確**。記号（\(\hbar,\omega,a,a^\dagger,N,\xi\)）が全節に渡るので表記の一貫性も試せる |

**書き方（チャットのみ）**

1. 主題だけ渡す —「1次元調和振動子を、生成消滅演算子による代数的解法から座標表示まで通して整理した論文を書いて」
2. 導出の粒度を詰める —「第3節、\([a,a^\dagger]=1\) からエネルギー固有値を出すところが飛んでいる。数演算子の固有値が非負整数になる理由を段階的に」
3. 構造を要求する —「基底エネルギーが \(\hbar\omega/2\) になることを定理として立てて、証明を分けて」
4. 参照を要求する —「エルミート多項式の漸化式の式を、座標表示の節から参照して」
5. 表記の統一 —「\(\langle x^2\rangle\) と \(\langle p^2\rangle\) の書き方が節ごとに違う。期待値は \(\langle\cdot\rangle_n\) に統一して」
6. 締め —「最後に不確定性積 \(\Delta x\,\Delta p=(n+\tfrac12)\hbar\) を導いて、\(n=0\) が最小不確定状態であることを述べて」

**完成条件**: 8〜12ページ。式番号が本文から参照され、導出に飛躍がなく、記号が全節で一貫している。

### 論文B — サーベイ

**テーマ**: ベルの不等式とその実験的検証

| | |
|---|---|
| 主眼 | 出典の扱いが実運用に耐えるか。**この環境の最大の弱点を突く題材** |
| 使う要素 | `citation`、`bibliography`、`citationRef`、`resolve_source`、引用スタイル切替 |
| なぜこれか | 学部で扱える題材のうち、**原論文が arXiv / DOI で確実に取れる**数少ない領域（Bell 1964、Aspect 1982、Hensen 2015、Big Bell Test 2018）。引用が主役になり、数式は CHSH 不等式程度で済む |

**書き方（URL をユーザーが供給する）**

1. 範囲を渡す —「ベルの不等式と実験的検証のサーベイを書きたい。まず構成案だけ出して」（＝**書かずに答えられるか**の確認も兼ねる）
2. 出典を貼る —「この論文を読んで、2.2 節に2段落で位置づけて」＋ arXiv URL / DOI
3. 数式は最小限 —「CHSH 不等式を導出して。局所実在論の仮定がどこで効いているか本文で明示して」
4. 主張と出典の対応 —「抜け穴（検出効率・局所性）の議論、どの実験がどちらを塞いだのか本文で対応づけて」
5. 体裁 —「参考文献を IEEE 形式に。本文の引用番号も揃えて」

> **既知の制約**: `search_sources`（文献検索）は AI Gateway 資格情報がある環境専用で、いまのローカル / OpenAI 直結では**使えない**。
> URL・DOI はユーザーが渡すか、モデルが知っているものを `resolve_source` で確認する経路しかない。
> 「文献探しから任せられるか」はこの構成では判定できないので、**別途ゲートウェイ環境で確認する**。

**完成条件**: 引用がすべて実在の取得済み出典に紐づき、本文の引用と参考文献リストが一対一で対応している。

### 論文C — 実験・計算報告

**テーマ**: 1次元有限井戸の束縛状態 — 超越方程式の数値解と無限井戸近似の比較

| | |
|---|---|
| 主眼 | 図表とデータの取り回し。手で数値を貼って紙面になるか |
| 使う要素 | `table`、`figure`(chart: line / bar → pgfplots)、`algorithm`、`codeBlock`、`callout`、`appendix` |
| なぜこれか | 学部の計算演習そのもの。**数値が並ぶ**（準位のエネルギー、井戸の深さ依存、誤差）ので表とグラフが自然に要る。二分法という書くべき手順があり `algorithm` が浮かない |

**書き方（数値を会話に貼る＋PDF クリック）**

1. 構成 —「有限井戸の束縛状態を、超越方程式の数値解と無限井戸近似で比較する報告を書きたい。まず構成を」
2. 数値を貼る —「この計算結果を表にして。列は n / 数値解 [eV] / 無限井戸近似 [eV] / 相対誤差」
3. 図にする —「井戸の深さ \(V_0\) を変えたときの束縛状態の個数を折れ線グラフに。横軸 \(V_0\) [eV]、縦軸 個数」
4. 手順を書かせる —「超越方程式 \(\tan(ka/2)=\sqrt{V_0/E-1}\) を二分法で解く手順を algorithm として書いて」
5. **PDF 上の表をクリック** して —「この列は要らないので落として」
6. **手動でブロックを直して** 紙面が自動で追随するか確認
7. 版を戻す —「さっきの表の変更を取り消したい」→ 変更履歴から復元

**完成条件**: 図表が本文から参照され、貼った数値が改変されずに出ている。

**完成条件**: 指定ページ数ちょうど、はみ出し・空白ページなし。

## 横断で確認する操作

論文 A〜D を書く過程で、以下がすべて自然に成立していること。

- [ ] チャットだけで最後まで進む（LaTeX を見せられない・書かされない）
- [ ] 質問・相談には**書かずに文章で答える**（勝手に紙面を作らない）
- [ ] PDF の要素をクリック → その要素だけが変わる
- [ ] 手動でブロックを編集 → 紙面が自動で追随する
- [ ] 版の復元 → 紙面がその版に戻る
- [ ] 実行中に停止できる／実行中に次の依頼を送れる
- [ ] 長い執筆でも会話の文脈を失わない（前の決定を聞き直さない）

## いま分かっている上限

論文を書く前から分かっている制約。これに当たったら「アプリの不足」として記録する。

- **画像を貼れない**。`figure` は `flowDiagram` と line/bar チャートのみで、写真・スクリーンショット・外部で作った図は載せられない（`assetId` は既存資産の参照専用）。実験系の論文では致命的になりうる。
- **文献検索が使えない**（この環境）。上記 B を参照。
- **文書クラスは `ltjsarticle` 固定**。IEEEtran や各学会のスタイルファイルは選べない。「投稿できる」の水準はここで頭打ちになる。
- **段組は 1 か 2、用紙は A3/A4/A5/B4/B5/letter**。それ以外の指定はできない。
- 使えるパッケージは amsmath / amssymb / graphicx / booktabs / array / ulem / geometry と、必要時に xurl / tabularx / longtable / amsthm / tikz / pgfplots。
