# 2026-09-16 フィードバック確認

対象は 0.1.24 に届いた4件。確認環境は macOS 26.4.1 / TeX Live 2024 / LuaLaTeX、開始時のソースは `98c05e3`。報告された macOS 26.6.2 と同一環境ではない。

| 報告 | 確認結果と対応 |
| --- | --- |
| ビルド失敗時に左の赤い点がない | 実Electronで未知のコマンドを含む文書をビルドして再現。Issues は error だが点を除去する実装だった。エラーがある間だけ赤い点を出すよう修正し、実画面で表示・成功後の消去を確認。 |
| 前回の生成ファイルを消さないと再ビルドできない | 目次・ラベル参照を含む文書で、成功→失敗→ソース修正→成功を実行。生成ファイルを手動削除せず復旧し、失敗中のPDFは直前の成功時とバイト一致。現時点では再現せず、ビルド処理は変更していない。元の文書・エンジン・ビルド設定・ログが必要。 |
| Axiom の返答が抽象的 | 保存済み評価の質問・回答を読み取り。質問は「式(1)の安定性条件は何か、この文書に書いてある範囲で答えて」。回答は条件と参照先ラベルがなく、rの定義だけあるという内容。元文書がないため正誤は未確定で、文書外の条件を補わない判断自体は妥当。別途、全回答に1〜2文・コード提示禁止を課していた共通プロンプトを修正。編集報告は短く、質問は必要な具体例・数式・根拠を返し、文書限定の依頼を守る。実モデルによる回答品質の改善は未評価。 |
| PDF とコードの同時表示が見つからない | ファイル一覧からPDFを開くとソースを置き換えてしまうことを実Electronで再現。新しく開くPDFを右グループへ送り、分割表示を有効化。ビルド後の未設定時も分割表示を初期値に変更し、明示的な保存済み別ウィンドウ設定は維持。修正後、ソースと実PDFの同時表示・ビルド後のPDF本文更新・別ウィンドウが増えないことを確認。 |

## 検証の範囲

- 既存のAI接続・編集・組版・復元・停止の完了済み検証は再実行していない。実AI APIは0回。評価記録は本番DBを読み取り、送信や変更はしていない。再ビルドの報告に診断ログは添付されていなかった。
- 修正前後の実Electronは一時ユーザーデータ・一時ワークスペースを使い、モデル用キーを渡さず、main側のネットワークfetchを遮断した。利用者の文書やインストール済みアプリは変更していない。
- renderer の `tsc -p web-src/tsconfig.json`、変更した共通プロンプトの構文確認を実施。MathLiveや未変更のAI UIは再ビルドしていない。生成されたrenderer JSをソースと一緒に更新。
- 実画面は赤い点・Issuesの発生行・ソースとPDFの左右表示・成功後の点の消去を確認。モデル出力を模擬して「品質改善済み」とする検証は行っていない。
- これはソース修正とローカル確認の記録。macOS/Windows向け配布版の公開は含まない。
